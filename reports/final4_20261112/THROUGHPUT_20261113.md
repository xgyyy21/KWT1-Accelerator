## 1. 三个口径的严格区分

赛题要的“任务”是**一次完整 FFN1 层计算**：M=99、K=64、N=256，1,621,632 次 MAC。

| # | 口径 | 起点 | 终点 | 包含什么 | 本次是否有数据 |
|---|---|---|---|---|---|
| 1 | 块级**计算**窗口 | START 被接受 | 最后一个 MAC 完成 | 只有 16 路 MAC 阵列流水 | ❌ 未单独测量，仅有结构推导 |
| 2 | 块级**任务**窗口 | START 被接受 | `accel_done` 拉高 | 计算 + 加速器主动读 A/B/bias + 写回 Y | ✅ 12 层均有（743,159 周期，100 MHz） |
| 3 | **正式 SoC 任务** | CPU 写 START | CPU 读到 done 并完成写回 | 上面全部 + E203 取指/调度 + 总线仲裁 + 共享 SRAM 延迟 | ❌ 待测 |

口径 2 的计数方式（`rtl_tb.sv` 第 188–191 行）：

```verilog
cycles = 0;
while (!accel_done && !accel_error && cycles < 30000000) begin
  @(posedge clk); cycles = cycles + 1;
end
```

时钟为 `always #5 clk = ~clk`，即 **10 ns = 100 MHz**（不是 150 MHz）。所以任何 150 MHz 数字都是**折算**，必须标注。

## 3. 计算过程

单任务 MAC 数：

```
99 × 64 × 256 = 1,621,632 MAC
```

### 3.1 块级纯计算（结构推导）

16 路并行，理论下限：

```
1,621,632 / 16 = 101,352 周期
@150 MHz (6.6667 ns) → 675.7 µs → 1,480 tasks/s
GOPS = 2 × 1,621,632 × 1,480 / 1e9 = 4.80 GOPS
```

**这是上限，不是实测**：没有单独的“计算窗口”日志，且实际 FSM 有流水填充与握手开销。

### 3.2 块级任务（实测，100 MHz）

```
743,159 × 10 ns = 7.4316 ms
任务/s = 1 / 7.4316 ms = 134.6
MAC/s  = 134.6 × 1,621,632 = 2.182e8  (0.218 GMAC/s)
GOPS   = 2 × 0.218 = 0.436
```

### 3.3 块级任务（按 150 MHz 折算）

```
743,159 × 6.6667 ns = 4.9544 ms
任务/s = 201.8
GOPS   = 0.655
```

**标注**：仿真在 100 MHz 下进行；150 MHz 只是综合/STA 的目标频率（setup WNS 0.00 ns），此行为折算值。

### 3.4 正式 SoC 口径（2026-11-13 实测 PASS）

## 4. 为什么块级 743,159 不能当硬件性能

同一个 RTL、同一形状，在另一版比较 TB 中记录到 **247,721 周期**（`~/kwt1_final4_rtl_gate_compare_20261113/`），是 743,159 的约 1/3。两次的 `a_reads/b_reads/bias_reads/y_writes` 完全相同（50,688 / 8,192 / 256 / 12,672），差异全部来自测试平台的存储模型时序：

```verilog
assign m_cmd_ready = rst_n && !response_pending && !m_rsp_valid &&
                     ((cycle_count % 5) != 0);
```

即每 5 拍插一个等待、且只有 1 个未完成响应。真实 SoC 的共享 SRAM 不会是这个时序。

因此：

1. 743,159 与 247,721 都是**块级、TB 相关**的数字，不能互相替代，也都不能当作硬件吞吐；
2. 只有口径 3（SoC 实测）才是赛题意义上的正式吞吐；
3. 报告里若要引用，只能写“块级任务窗口，含测试平台存储模型”。
