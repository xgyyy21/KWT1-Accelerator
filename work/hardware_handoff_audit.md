# 软件与硬件交接：事实及依赖核对

本文件供交接文档作者核查。赛题事实来自 [2026 年芯片设计赛道官方指南](https://mp.weixin.qq.com/s/XQrz5_71pYRwk-U0qIl4SA)，细节见 [contest_audit.md](contest_audit.md)；现有工程状态见 [software/README.md](../software/README.md) 和 [driver/README.md](../software/driver/README.md)。**官方没有替团队制定寄存器表、最终量化格式、SRAM 地址图或 System Bus/NICE 选择。**下表里的接口文件是建议的团队交接物，不应写成官方指定名称。

## 先分清两种“必须”

- **竞赛必做：**本科任务 1–3，即长度 64 的点积和数值处理、`99×64 @ 64×256 + b` 的第一前馈线性层、12 层参数依次切换、E203 SoC 集成与驱动/验证/综合。RTL 的计算结果必须与团队软件数值模型逐位一致；按层聚合的 12 层最大 NRMSE 不超过 3%。要提交 RTL、测试平台、驱动、格式说明、转换脚本、数值模型、综合网表、SDC、时序/面积/功耗/性能记录等。GELU、第二线性层、注意力和整模型推理均非本科必做。
- **团队必须自行拍板：**总线接入、寄存器/指令、内存布局与数据搬运、定点或浮点表示、计算顺序与舍入溢出、缓冲分块、任务握手。这些是履行必做任务的设计决策，但不存在可从官方指南直接抄来的最终答案。
- **现有软件仅为起步工程：**参考提取器尚未在兼容 TensorFlow 环境运行真实 KWT-1；`prototype_fixedpoint.json` 和 `.mem` 布局是可改的示例；C 驱动是抽象回调骨架，未接 E203。不能将本地单元测试通过写成 12 层实际精度或 SoC 验收通过。

## 按依赖顺序向硬件同学索取什么

| 最迟阶段 | 需要硬件同学交给软件同学的可检查成果 | 为什么软件需要 | 依据/性质 |
|---|---|---|---|
| **0. 两边并行启动时** | 一页共同认可的计算边界：仅 FFN1、`X[99,64]`、`W[64,256]`、`b[256]`、`Y[99,256]`，12 组参数按层号 `0..11` 更换；确认 `W[k,j]` 的意义、偏置加入点、是否只做一层一次任务。 | 防止软件打包成转置权重，或把 GELU/第二层误算进硬件任务。 | 矩阵规模与 12 层切换为官方必做；元素排布说明需团队固化。 |
| **1. 数值模型冻结前，优先** | **共同签字的数值契约及对应 RTL 算术单元：**X/W/b/乘积/累加/Y 的位宽、有符号性、缩放或小数位、量化与反量化、每一步乘法和累加的计算顺序、偏置加入位置、舍入点和 tie 规则、饱和还是回绕、溢出行为、输出编码。至少给一个含负数、半整数、最大值、溢出的逐步手算示例和仿真结果。 | 软件要把 `ffn1_numeric.py` 改成**逐位一致**的黄金模型，才能正确选择量化参数、生成期待输出和定位误差。若先大批打包再改 RTL，会整批作废。 | 官方要求软件数值模型与 RTL 逐位一致、报告舍入溢出与误差来源；具体格式由团队选。 |
| **2. 生成 RTL 输入文件与驱动适配前** | **数据布局契约：**X/W/b/Y 的逻辑形状、线性地址公式、字节序、每元素字节数、对齐和步长；若 16 位 SRAM 宏中装 8/32/48 位数，规定字序、符号扩展和有效位；块尺寸、块顺序、padding、每层参数如何放置；至少一组小矩阵 `X/W/b` 的字节镜像和 RTL 读到的元素表。 | Python `pack_tensors.py`、C 驱动、RTL 地址发生器要读写同一字节流；任何一处转置或字序不一致都会造成错误。 | 官方规定内部 SRAM 宏规格及共享 512 KB SRAM；具体布局/分块是团队决策。 |
| **3. | **4. 联调和性能测试前** | **可运行的 RTL/SoC 仿真工程：**加速器顶层端口、E203 平台工程版本、时钟/复位、SRAM 模型、总线连接、测试平台、运行命令；给一份正常值及边界值的输入/预期/RTL 实际输出对拍日志，覆盖换层、复位、连续任务、错误状态。提供输出写回完成的可观测事件和周期计数方法。 | 软件将真实任务送入仿真、逐元素比特对拍，复现任务时间；单有算术模块仿真不能证明 SoC/驱动工作。 | SoC 集成/仿真、功能场景、完整写回和性能记录为官方必做。 |
| **5. 综合/提交前** | **冻结版 RTL、约束和报告：**综合脚本与库/工艺配置、SDC、网表、时序报告、面积（加速器/接口/内部 SRAM 分项）、功耗估计和对应 SAIF/VCD、任务周期/吞吐/能耗、版本及哈希。标明结果与哪版数值配置、驱动、镜像相配。 | 软件侧报告、交付清单、复现实验需对应同一冻结配置，避免精度与面积/功耗来自不同版本。 | 官方 150 MHz 时序目标、2.25 mm² 新增加速器面积上限、综合功耗和一致冻结配置要求。 |

## 两人可并行做的工作

- **软件不等硬件即可做：**在指定 ARM KWT-1 固定提交和 `best_weights` 上搭兼容环境；用合法音频提取 12 层 `X/W/b/Y_float`，核对 `Y_float ≈ X@W+b`；准备无梯度标定与验证样本、误差汇总脚本、模型/数据来源清单；完善通用驱动流程和 mock 测试。此时尚不能声称最终数值精度或 RTL 一致。
- **硬件不等软件真实数据即可做：**确定 System Bus/NICE 路线，研究 E203 平台工程、SRAM 宏和接口；用自造小矩阵做 64 点积、偏置、缓冲、控制及写回 RTL，完成基本复位/连续任务验证；估算面积和 150 MHz 时序。自造测试只能证明逻辑起步，不能代替官方 KWT-1 验证。
- **要共同决定：**数值契约与数据布局，最好先选一个小样例互相独立手算/仿真，再冻结。软件可提出精度与存储压力，硬件可提出面积、时序、乘法器与 SRAM 约束；不能一方单方面宣布格式已定。

## 关键边界和易误解处

1. 官方给的 **150 MHz** 是统一时钟/综合时序目标，不是已跑通的实际最高频率。**2.25 mm²** 是新增加速器、接口逻辑及内部 SRAM 宏之和的上限，不含复用 E203、共享 512 KB SRAM 和固定总线/外设；面积来自综合报告，不靠猜。
2. 官方的性能任务从**输入和参数开始装载**到**结果全部写回结束**，含参数装载、总线等待及 E203 调度；PC 音频预处理、一次性格式转换和统一分类头不计。驱动 README 将外层计时表述为“读回后”，应在团队计时协议中明确：若 CPU 读回只是验证，应单列其耗时，不要把 `DONE` 或纯算术周期当成官方任务周期。要在 SoC 仿真中给出计时起止事件的可复现记录。
3. 共享 SRAM 为 512 KB；加速器内部 SRAM 只能用指定 `16×128/1024/4096` 宏组合。数据怎么进、出、换层，CPU 还是 DMA 搬、是否持续供块，都会改变驱动回调协议和计时。尤其在硬件尚未决定是否边算边供块时，现有驱动“先全部装载再启动”的骨架还不能视为最终方案。
4. 必做乘加必须由 RTL 硬件完成。软件参考模型、打包器和 E203 驱动负责准备数据、定义规则与核验结果，不能把结果预先算好再伪装成硬件输出。
