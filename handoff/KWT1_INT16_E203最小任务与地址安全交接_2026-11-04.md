# KWT-1 INT16 / E203 最小任务与地址安全交接

日期：2026-11-04
范围：硬件侧本地 RTL、System Bus adapter、最小任务和 DTCM 地址安全测试

## 1. 本轮完成内容

1. **sysper 控制寄存器**：修正 `int16_system_bus_control.sv` 的端口声明，保留 32 位 ICB 控制窗口和 `CTRL_BASE` 参数。寄存器 offset 为 `CTRL=0x00、STATUS=0x04、SRC_A=0x08、SRC_B=0x0c、DST=0x10、M=0x14、K=0x18、N=0x1c、BIAS=0x20、SHIFT=0x24`。
2. **ext2dtcm adapter**：新增 `rtl/int16_e203_system_bus_adapter.sv`。控制端接 `sysper`，数据端接 `ext2dtcm`；外部使用全局 byte address，adapter 先检查完整 DTCM 窗口和 4-byte 对齐，再转换成 18 位本地 offset。越界或未对齐请求返回 error，不直接截低位。
3. **非严格最小形状**：testbench 实例化 `STRICT_COMPETITION_SHAPES=0`，支持软件提供的 `M=1,K=64,N=16` 向量。正式比赛形状仍可通过参数重新打开。
4. **软件向量**：归档 `handoff/int16_e203_minimal_2026-11-03/`，包含 `manifest.json、x.mem、w.mem、bias.mem、y_expected.mem`。bias 为低字在前、高字在后；输入和输出每行一个 16 位字。
5. **真实 RTL 轨迹**：新增 `tb/int16_e203_minimal_tb.sv`，输出 System Bus/ext2dtcm 请求、响应、状态和写回轨迹 CSV。
6. **DTCM 地址专项**：第一轮使用 `A=0x90000000`、全 1 输入，期望输出 16 个 `0x0040`；第二轮使用 `A=0x90008000`、全 2 输入，期望输出 16 个 `0x0080`；第三轮使用 `0x90040000`，要求进入 ERROR。
7. **固定入口**：`rtl/files.f` 已加入新增 adapter；`integration/int16_e203_minimal.f` 固定 RTL+TB 文件列表；`scripts/Run-Int16E203Minimal.ps1` 可复现编译、运行和证据哈希生成。

## 2. 本机实际仿真结果

工具：Icarus Verilog 14.0 devel，路径 `D:\competition\.tools\iverilog\bin`。

执行入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Run-Int16E203Minimal.ps1
```

结果：

```text
PASS int16_e203_minimal_tb first=16x0040 mirror_test=16x0080 out_of_window=ERROR commands=1152 responses=1152
```

额外回归：

- `int16_pe_mac_tb`：PASS，覆盖 INT32 乘积、INT48 累加、RNE、饱和、保留值 `0x8000` 和 K=64/K_TILE=32 延续。
- `int16_accelerator_top_tb`：PASS，覆盖 K=64、K=256、不复位连续两任务和 32 位总线响应计数。

这些是本地行为级 RTL 仿真结果，不是服务器 E203、真实 DTCM 宏或 ASIC STA 结果。

## 4. 当前结论边界

已通过：

- 本地 INT16 PE 和顶层行为级 RTL；
- 本地 sysper 控制握手；
- 本地 ext2dtcm 单 outstanding、背压和响应保持模型；
- 32 位总线承载两个相邻 INT16 的最小任务；
- 本地 adapter 对 `0x90000000` 和 `0x90008000` 的地址区分；
- 本地越界地址错误响应。

尚未通过或尚未验证：

- 服务器真实 E203 工程中的实例接线；
- 真实 `RAMSP8KX32` 宏的动态地址镜像；
- 服务器启动文件、链接脚本和 CPU smoke；
- 真实平台 cache/fence、CPU 可见性和 DTCM 保留区；
- 综合、正式 PVT、150 MHz STA、面积和功耗。

特别说明：本地大数组模型能证明 adapter 译码和计算流程，但不能替代真实 SRAM 宏的地址宽度验证。综合同学仍需在服务器用真实宏重复地址配对测试。
