# INT16 软件量化数据接入说明

本包可接收软件侧导出的十进制 CSV，检查形状、数值范围及数据类型，然后生成 testbench 使用的有符号十六进制内存文件。

## 软件侧输入

提供一个目录，包含 manifest.json、a.csv、b.csv、bias.csv 和 expected.csv。CSV 不带表头：

- a.csv：M 行、K 列，signed INT16，行主序。
- b.csv：K 行、N 列，signed INT16，行主序。
- bias.csv：N 行、1 列，signed INT32。
- expected.csv：M 行、N 列，signed INT16。

manifest 需要描述 version=1、M/K/N、out_shift、四种 dtype、row-major 布局、nearest_ties_away 舍入、saturate 溢出策略及四个 CSV 文件名。out_shift 必须来自软件参考计算的实际参数；bias 必须已经量化到 A×W 累加尺度。

## 运行

在硬件仓库根目录执行：

    python scripts/Prepare-Int16QuantizedData.py --manifest path\to\manifest.json --out build\quantized_job
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\Test-Int16QuantizedData.ps1 -PreparedDirectory build\quantized_job -OutputDirectory build\quantized_run

准备脚本会生成 a_int16.mem、b_int16.mem、bias_int32.mem、expected_int16.mem 和 prepared_manifest.json。manifest 记录原始CSV与输出文件的 SHA-256。testbench 使用 System Bus mock 驱动正式 INT16 顶层，逐项核对 M×N 的写回结果。

当前入口覆盖赛题的 M=99、N=256、K=64 或 K=256。该测试是可复现的数值功能对拍入口，不代表真实E203接线、实际SRAM宏实例、150MHz时序、PPA或12层NRMSE已通过。平台地址窗口、ICB仲裁及正式SRAM cache/DMA仍需后续集成。
