# KWT-1 INT16 PE v1 冻结合同

日期：2026-11-02
状态：INT16 单PE、16-PE 阵列和 System Bus 原型已按本合同实现；FP32 正式计算合同停止扩展。软件候选 Golden 的完整对拍结果见 `INT16_软件量化数据RTL对拍报告_2026-11-03.md`。

## 已冻结的选择

- A/B：有符号int16。
- 乘积：有符号int32，完整保留16x16乘法结果。
- 累加器：有符号int48。K=64最坏乘积累加加int32 bias仍不会溢出int48，因此累加过程不截断、不饱和。
- bias：有符号int32，与乘积累加值处于同一量化尺度；进入PE后符号扩展到int48再相加。
- 正式输出：有符号int16。先对int48累加值加int32 bias，再执行可配置算术右移、舍入和饱和。
- 舍入：round-to-nearest，恰好一半时取偶数（ties-to-even）。
- 输出溢出：饱和到[-32767,32767]，禁止直接截断；`-32768` 为保留编码。
- 输入 `0x8000`：按非法保留编码处理，PE 报告 `input_error`，顶层进入 `ERROR`，不写回该任务结果。
- Q格式：PE不硬编码固定Q值。由软件给出每层out_shift；A、W和bias量化脚本必须保证bias已换算到A乘W的累加尺度。
- K=64、K_TILE=32保持不变。前32次MAC结束后不清累加器，第33次继续使用同一个int48部分和，只在全局K-1断言mac_last。
- 第一版阵列规模冻结为16个PE。当前 RTL 已完成 16-PE 阵列复制和整层 System Bus 原型；真实软件候选数据对拍中 7 层逐位通过，5 层各有 1 个中点舍入差异，未将整体标记为 PASS。
- 不再保留FP32的8拍乘法加4拍加法合同。最小PE当前每拍接受一个MAC；150MHz仍需综合验证后再决定内部寄存器切分。

## 总线与SRAM

- System Bus为32位ICB，一个命令携带两个相邻int16：低地址元素在wdata[15:0]，高地址元素在wdata[31:16]。
- 参数、输入、bias和输出均不再使用FP32高低半字拼接，一个SRAM word就是一个int16元素。
- 不加入FP32/INT16数据类型转接器，不修改已验证的RAMSP128X16 wrapper。
- RAMSP128X16仍是单次16位宏访问。32位ICB命令在System Bus/存储控制器边界映射为两个相邻16位word；这是总线事务展开，不是数据类型转换。

## RTL接口

start可与第一个mac_valid同拍，用0作为该次acc_before。每个mac_valid产生product和新的accumulator。只有全局最后一个MAC同时置mac_last，该拍输出raw_sum和量化后的int16结果，并产生单拍result_valid。

为联调保留trace_product、trace_acc_before、trace_acc_after；它们是RTL真实路径，不是软件生成轨迹。

## 暂未包含

本版本仍不是最终平台实现：不包含真实 E203/SoC 接线、实际 SRAM 宏实例、整层 DMA/cache 集成、官方独立验证集精度结论，也不宣称综合/150MHz 或 PPA 通过。System Bus memory mock 下的整层写回和软件候选数据对拍仅作为当前硬件原型证据。
