# KWT-1 硬件阶段交接：Wrapper 修复与待确认事项

日期：2026-11-02  
分支：`hardware`  
状态：standalone 功能回归通过；等待软件和综合/平台侧复核。本文件不代表真实 E203/SoC 或 PPA 验收。

## 本轮修复

1. NICE 通用配置读写只允许访问已定义的七个配置寄存器。对 CTRL/STATUS、未对齐地址、越界地址和不支持的指令返回该条 NICE 响应错误，不再将无效写操作报告为成功。
2. 增加 START 保护窗口：START 接收后立即响应“命令已接受”，但 `start_guard` 一直保持到任务完成或作业错误，覆盖 BUSY 尚未拉高的启动间隙。保护期间拒绝重复 START、配置写和 CLEAR。
3. 区分命令错误与作业错误。非法/忙时命令只通过 `nice_rsp_err` 报告，不污染 STATUS.ERROR；作业错误仍由加速器状态寄存器报告。
4. 固定本轮提案中的状态规则：新 START 清除上次粘滞 DONE/ERROR；空闲时可显式 CLEAR；CLEAR 与 DONE/ERROR 同周期发生时事件优先；STATUS 读取无副作用。
5. 复位期间抑制 NICE request-ready/active，并补齐 Wrapper 协议、启动窗口、CLEAR 优先级、复位及连续任务测试。SRAM 测试覆盖 16-bit 传输、地址 127/128/1023、读响应背压、standby 与复位保留。

## 本轮验证

Icarus/vvp 14.0 下 7 项硬件功能/稳健性测试全部通过，进程退出码均为 0。完整工具版本、命令、逐项日志、输入源码快照及 SHA-256 清单见 [v4 回归证据](evidence/hardware_independent_checks_2026-11-02_v4/)。归档内 96 个证据文件的哈希已复核。

本轮没有运行 Yosys/Slang，没有使用供应商 SRAM 时序模型，没有连接真实 E203，也没有运行 SoC 或完整 FFN1 回归。当前 NICE 指令编码是 mock 测试编码，不能作为软件 ABI；v3 控制接口仍是硬件提案，等待三方确认。

## 请软件侧确认/提供

1. 是否接受“空闲时新 START 清除旧 DONE/ERROR”，还是 ERROR 后必须先 CLEAR 才允许重试；命令响应错误与 STATUS.ERROR 分离是否符合驱动处理预期。
2. STATUS 保持只读、未定义位为 0，以及 CLEAR 与同周期 DONE/ERROR 事件时“事件优先”的规则是否接受。
3. 提供真实 NICE 指令的 opcode/funct 位级编码、汇编/编译器发射样例，并说明 CPU 软件如何观察 `nice_rsp_err`。
4. 明确 System Bus 的 byte/word 地址换算、数据写完成定义，以及 DONE 后 CPU 读到结果的可见性、屏障和缓存维护要求。
5. 若需要修改数值或任务行为，请提供对应的软件参考输入/期望结果与验收边界；本轮回归没有重跑真实模型整层。

## 请综合/平台侧确认或提供

1. 用本轮推送后的固定提交复核 standalone RTL 的可综合性、warning 和综合前端兼容性；本轮未运行 Yosys/Slang。
2. 提供正式综合/STA 所需的顶层、完整 filelist/include 路径、宏定义、时钟与复位约束，以及比赛标准单元和 SRAM Liberty/DB、PVT/RC 条件、宏参数配置。
3. 复核 Wrapper 和新增 adapter 的 E203 NICE 真实端口连接、`E203_HAS_NICE` 构建条件、实例位置及真实构建命令；当前 adapter 仍是独立骨架，未接入 `e203_subsys_nice_core`。
4. 确认真实 SRAM 模型/宏下的读数据更新和保持、背压、连续读写及 EMA/EMAW 设置，并提供仿真或库配置结果；本轮测试使用功能模型，不能证明宏时序/PVT。
5. 确认 NICE 响应错误如何到达 CPU，以及 System Bus 写完成、共享 SRAM 可见性和控制 DONE 的平台级时序合同。
