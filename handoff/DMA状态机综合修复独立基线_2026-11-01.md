# DMA 状态机综合修复独立基线

日期：2026-11-01

## 修改目的

`rtl/fp32_tile_dma_sequencer.sv` 原先在 `always_ff` 内调用 `advance_half_or_element` task。为避免严格综合前端将 task 调用误判为额外状态驱动或不规范时序结构，本版本删除该 task，并将其状态更新逻辑直接内联到唯一的 `always_ff @(posedge clk or negedge rst_n)` 中。

本修改不改变：

- A、B、bias、result 四个阶段的访问顺序；
- FP32 低 16 位/高 16 位传输顺序；
- 行、列、K 索引的边界转移条件；
- `ENABLE_RESULT_WRITE`、`DONE` 和错误接口语义；
- 数据地址布局和外部总线信号定义。

本文件 SHA-256：`8f25945b8f222fab45474915f61c3ea3171be1e76161c4472a182e59e254b61b`。

## 本地回归

使用 Icarus Verilog/vvp 14.0 devel，当前工作区源码快照运行 `scripts/Test-SramComputeIntegration.ps1`，输出目录：

`build/dma_sequencer_inline_regression_2026-11-01_v1/`

结果：**9/9 通过，0 失败，编译和仿真退出码均为 0**。

其中两组 Golden FFN1 归档实际测试源码 SHA-256 与当前文件完全相同；因此软件侧已签收的两组归档数值/写回结果覆盖的就是本次内联后的 DMA 源码字节，不是原始 `995a934` 中的 task 版本。

覆盖项目包括：

- SRAM bridge 仲裁及 standby 恢复；
- SRAM/计算集成的两个连续任务（8×16、尾块 3×5）；
- DMA load engine；
- cache streamer；
- 2×2、8×16、K=64、K=256 分块计算；
- 顶层两个端到端任务。

本轮结果只能证明当前 RTL 在项目功能模型下的行为没有因内联修改发生回归。Icarus 不是目标综合工具；本机未发现可执行的 Yosys/Slang，Verilator 文件在当前 Windows 环境下也无法直接执行，因此尚无本地正式综合网表或时序结论。
