# INT16 PE 两周期结果流水化交接

日期：2026-11-04
基线：`fa288f6`
本次版本：待提交

## 1. 修改原因

综合侧在单 PE 的 SS 慢角探索中发现，原路径为：

```text
INT16 乘法 → INT48 累加 → bias 加法 → RNE/右移/饱和 → result_out 寄存器
```

TT 条件下 setup slack 只有约 `+0.019 ns`，SS 条件曾出现约 `-4.669 ns` 和 `-5.610 ns` 的违例。此前一次自动优化在 180 秒上限内没有形成最终网表，因此不能把它当作有效优化结果。

本次只实施综合同学建议的低影响局部修改：保留 MAC 反馈路径，在最后一次 MAC 之后分离 bias 加法和结果重定标；不修改阵列、System Bus、DMA、E203 adapter 或软件寄存器 ABI。

## 2. RTL 修改

修改文件：

```text
rtl/int16_pe_mac.sv
```

末次 MAC 的时序现在为：

| 阶段 | 动作 |
|---|---|
| E0 | 接受最后一个乘积，更新 accumulator/trace，同时锁存包含最后乘积的 `acc_after`、当前 bias 和 `out_shift` |
| E1 | 对锁存的 `acc_after` 加符号扩展 bias，得到 `biased_sum_q` |
| E2 | 对 `biased_sum_q` 执行原有 RNE、右移和饱和，更新 `raw_sum_out/result_out`，产生一个周期的 `result_valid` |
| E3 | 顶层看到 `result_valid`，进入既有结果写回流程 |

关键保证：

- 最后一项乘积使用 `acc_after_comb`，不会漏掉最后一项；
- bias 只加一次；
- bias 和 shift 锁存于最后一次 MAC，不依赖后续输入端口保持；
- `trace_valid/product/acc_before/acc_after` 仍在每个 MAC 接受周期产生，没有额外延迟；
- 复位清除两个 pending valid 和中间寄存器；
- 顶层已有 `S_RESULT` 等待 `pe_result_valid`，不需要固定倒计时或改变总线接口。

结果处理期间不接受新的点积输入。当前顶层在最后一次 MAC 后进入 `S_RESULT`，满足这一约束；若未来需要重叠任务，必须增加 ready/busy 和上下文管理，不属于本次修改。

工具：Icarus Verilog 14.0 devel。测试命令使用当前 `rtl/files.f` 和对应 testbench。

`tb/int16_pe_mac_tb.sv`：PASS。

覆盖：

- INT32 乘积、INT48 累加；
- K=64 和 K_TILE=32 跨边界；
- RNE ties-to-even；
- shift=0、1 等结果；
- 正负饱和；
- bias 正负值；
- 最大合法操作数；
- `0x8000` 非法输入；
- 明确验证 E0 无 result、E1 无 result、E2 才产生 result_valid；
- 最后一项 MAC 后改变输入 bias/shift，结果仍使用末次 MAC 锁存值。

### 顶层连续任务

`tb/int16_accelerator_top_tb.sv`：PASS。

- K=64 任务通过；

## 4. 当前结论边界

已确认：

- 新 PE 结构可编译；
- 数值结果与修改前合同一致；
- 末次 MAC 的两周期结果处理时序符合预期；
- 顶层写回和 DONE 流程未因延迟改变而失败。

尚未确认：

- SS 慢角普通 MAC 反馈路径的 slack；
- SS 慢角 bias 阶段和重定标阶段的 slack；
- FF hold；
- 面积、寄存器增加量和完整任务周期变化；
- 目标工艺库下是否满足 150 MHz。

本地 Icarus 仿真不能证明时序达标，也不能替代 DC/STA。

## 5. 请综合侧复核

请以本次固定提交为输入，先核验 RTL 文件 SHA-256，再在已知 SS 两个候选温度条件下分别报告：

1. `accumulator.Q → accumulator.D` 普通 MAC 反馈路径；
2. `pending_acc_q/pending_bias_q → biased_sum_q` bias 阶段；
3. `biased_sum_q → result_out` 重定标路径；
4. FF hold；
5. 面积、寄存器数量和完整任务周期。

如果慢角仍不满足，再决定是否继续拆分重定标或对乘法/累加路径做更高风险的流水化。当前不应仅凭本次局部结构修改宣称满足 150 MHz。

## 6. 软件侧影响

寄存器、数据格式和数值合同没有改变。唯一可见变化是：最后一次 MAC 到首个写请求增加约两个时钟周期，软件的本地超时预算应保留余量。软件侧可使用原有 INT16 输入和 Golden 重新跑 PE/顶层对拍；真实 CPU/SoC 运行仍需等待服务器接线和综合侧确认。
