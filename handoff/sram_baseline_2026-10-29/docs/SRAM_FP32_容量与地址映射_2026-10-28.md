# FP32 SRAM 容量与地址映射 v1

日期：2026-10-28。对应本轮任务一；状态：已制定容量保持方案，宏引脚适配层已实现，尚未接入原计算通路。

## 依据与范围

依据老师的《硬件设计实现.txt》：8×16 PE，A/B/第三缓存各 16 bit×1024；FP32 占两个存储字；K_TILE=32。主办方 11 页资料给出的单颗宏是 RAMSP128X16，只有 128×16，不能把原来的一块 1024 字缓存直接替换为一颗宏。

本方案继续使用 FP32，不改变数值规则。保留三块逻辑缓存的容量，各用 8 颗宏扩展深度，共 24 颗。这是硬件侧提出并实现的组织方案，不表示主办方已确认允许的宏数量，也不是物理宏已完成实例化。宏数量、库视图和物理连接仍需平台/综合侧核对。

## 容量表

| 对象 | 逻辑容量 | 当前 8×16、K=32 tile 的有效数据 | 所需 128×16 宏 |
|---|---:|---:|---:|
| A 缓存 | 1024×16 = 2048 bytes | 8×32 个 FP32 = 512 个 16-bit 字 | 8 |
| B 缓存 | 1024×16 = 2048 bytes | 32×16 个 FP32 = 1024 个 16-bit 字 | 8 |
| C/第三缓存 | 1024×16 = 2048 bytes | 当前计算通路存 bias：16 个 FP32 = 32 字 | 8 |
| 合计 | 3072 个字 = 6144 bytes | 不包含 PE、预取寄存器、result_stage | 24 |

按当前有效负载缩小 A/C 容量可以进一步减少宏数量，但本轮保留老师提出的三块 1024 字容量，避免先改变既有缓存地址宽度与模块容量合同。

当前 `fp32_tile_load_compute.sv` / `fp32_kblock_load_compute.sv` 中，第三缓存用于 bias；最终 128 个 FP32 输出保存在 `result_stage` 寄存器，共 4096 bits = 512 bytes。不能把这些寄存器说成已装入第三 SRAM。跨 K 部分和主要由 PE 寄存器保持；已有独立 checkpoint 实验不是这条生产通路的默认宏连接。

若后续专门为 checkpoint 配置独立 512×16 存储，将另需 4 颗宏，或先确定与其他缓存复用的排他调度。本轮 24 颗不包括独立 checkpoint 存储，也未改变保存恢复方案。

## 逻辑地址到宏地址

适配层提供 A/B/C 三个独立请求通道，银行编号只用于文档和轨迹，不是新增的 CPU 寄存器定义：A=0、B=1、C=2。

对每个 bank 的 10-bit **16-bit 字地址** `word_addr`：

```text
slot          = word_addr[9:7]          // 0..7，选择本 bank 的宏
macro_A       = word_addr[6:0]          // 0..127，送入宏的 A[6:0]
flat_macro_id = 8 * bank + slot         // A:0..7，B:8..15，C:16..23
```

| bank | 字地址 | 扁平宏编号 | 宏内 A |
|---|---:|---:|---:|
| A | 0 | 0 | 0 |
| A | 127 | 0 | 127 |
| A | 128 | 1 | 0 |
| A | 511 | 3 | 127 |
| A | 1023 | 7 | 127 |
| B | 0 / 1023 | 8 / 15 | 0 / 127 |
| C | 0 / 1023 | 16 / 23 | 0 / 127 |

一个 bank 每拍最多只选中其中一颗宏。即使 bank 内部有 8 颗宏，本接口也不提供 8 路并行请求。A/B/C 独立访问时可合计完成最多三个 16-bit 操作；这来自三套独立存储，而非一颗宏有三个端口。

10-bit 接口本身只能表示 0..1023。上层宽地址必须先做范围检查，不能先截断再希望适配层发现越界。此模块没有 CPU 地址解码、非法 bank 编号或总线错误接口。

## FP32 本地布局

沿用 `rtl/fp32_tile_cache_mapper.sv`，每个 FP32 低半字先访问，高半字后访问。`h=0` 表示 bits[15:0]，`h=1` 表示 bits[31:16]。

| 对象 | 16-bit 字地址公式 | 有效范围 |
|---|---|---|
| A[row,k] | `2*(row*32+k)+h` | row=0..7，k=0..31，字地址 0..511 |
| B[k,col] | `2*(k*16+col)+h` | k=0..31，col=0..15，字地址 0..1023 |
| bias[col]（C） | `2*col+h` | col=0..15，字地址 0..31 |
| 输出[row,col] 的逻辑序列 | `2*(row*16+col)+h` | 0..255；当前来自 result_stage，并非 C 宏已保存 |

同一 bank 搬运一个 FP32 至少需要两次访问，不能一拍请求 32 bits。正式 tile 布局的低半字地址均为偶数；测试额外使用 127/128 拆半字仅用于覆盖宏切换，不能据此更改正式布局。

不足 8 行、16 列或 K=32 的尾块仍由上层装载/预取逻辑补零并过滤无效输出；SRAM 复位不会自动补零。新任务必须重新装载要使用的位置，不能把未初始化 SRAM 当成零。

## 整层不是全部驻留于本地缓存

首个 FFN1 的完整 X 需 12,672 字，W 需 32,768 字，bias 需 512 字，Y 需 50,688 字。本地三块缓存只装当前 tile，整层仍需上层搬运和写回。完整地址窗口、CPU 字节地址与内部半字地址转换、缓存一致性、NICE/System Bus 协议不在本轮新增定义，需真实 E203 平台确认。

## 下一步接入边界

本轮新增 `sram_1024x16_adapter.sv` 和 `sram_fp32_cache_adapter.sv`，保留旧 `matrix_cache_manager.sv`。后续任务四需接入请求仲裁/等待、偏置装载、预取和写回控制，再运行受影响的缓存及整层回归。旧模型支持的同 bank 同拍读写不能原样带入这个单端口接口。
