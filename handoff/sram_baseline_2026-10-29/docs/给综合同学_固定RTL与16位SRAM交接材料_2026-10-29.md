# 给综合同学：固定 RTL 与 16 位 SRAM 交接材料

日期：2026-10-29

## 固定入口

- 顶层：`rtl/fp32_accelerator_top.sv`
- RTL 文件列表：`rtl/files.f`
- SRAM 逻辑 bank：`rtl/sram_1024x16_adapter.sv`
- 三 bank 组合：`rtl/sram_fp32_cache_adapter.sv`
- 物理宏端口：24 个 128x16 单端口宏，每个逻辑 bank 由 8 个宏组成。

本交接包中的 RTL 是本机快照，由 `source_manifest.csv` 和 SHA-256 固定；当前工程没有可引用的 Git 提交号，不能把快照称作已提交版本。

包内 `VERSION.json` 给出由源码清单生成的版本标识。主 RTL 与本轮完整双任务实际编译快照逐文件相同；新增异常 TB 和独立故障候选模块另行实测。顶层无需纳入 `rtl/prototype/`，`rtl/files.f` 不包含故障候选模块。包中 `tb/` 与自编 SRAM 功能模型只用于仿真，不作为可综合存储宏。

**当前顶层只导出 24 组宏引脚，未在 DUT 内实例化工艺 SRAM。** 平台集成者需另建宏 wrapper，连接 `CLK` 和各宏引脚，提供 Liberty/LEF/网表等。未绑定宏时，不能将导出端口的逻辑面积当成含 SRAM 的芯片总面积。

## 16-bit SRAM 端口约定

- 每次请求数据宽度为 16 bit；FP32 通过低半字、高半字两次请求传输。
- 逻辑地址为 10 bit，地址 `[9:7]` 选择 128x16 宏，`[6:0]` 为宏内地址。
- 读请求接受后产生一个响应槽；响应未被接受时，bank 不再接受后续请求。
- standby 时 `req_ready=0`，宏不被选中；`RET1N` 固定为有效工作值，不将 standby 与 retention 混用。
- 复位只清除控制器和响应状态，不清除 SRAM 宏内容。
- 每个 bank 每拍最多一个宏操作；不同 bank 可以并行。

下表方向相对于单颗 SRAM 宏（顶层输出接宏输入，`Q` 反向接回顶层）。第 `b` 个逻辑 bank 的第 `s` 颗宏对应扁平索引 `8*b+s`，`b=0..2`，`s=0..7`。

| 宏引脚 | 位宽 | 相对宏方向 | 连接/语义 |
|---|---:|---|---|
| CLK | 1 | 输入 | 顶层 `clk`，上升沿操作 |
| CEN | 1 | 输入 | `macro_cen[i]`，低有效；standby 为 1 |
| GWEN | 1 | 输入 | `macro_gwen[i]`，低有效写；读为 1 |
| WEN | 16 | 输入 | `macro_wen[i]`，完整写 0000，其他 ffff |
| A | 7 | 输入 | `macro_a[i]`，逻辑 word 地址 `[6:0]` |
| D | 16 | 输入 | `macro_d[i]`，一次仅一个半字 |
| Q | 16 | 输出 | 接 `macro_q[i]`；读响应槽根据宏编号选择 |
| EMA | 3 | 输入 | `macro_ema[i]`，当前固定 2 |
| EMAW | 2 | 输入 | `macro_emaw[i]`，当前固定 3 |
| RET1N | 1 | 输入 | `macro_ret1n[i]`，固定 1，未实现动态 retention |

宏没有项目 `rst_n` 引脚。三个 bank 均为 1024×16，即每 bank 8×128×16；总容量 6144 bytes。A 当前块用 512 个 halfword，B 用 1024，bias 用 32。结果暂存在 result_stage，PE 寄存器延续部分和；不要假设第三 bank 同时保存全部结果/部分和。

主办方 11 页原始图片位于包内 `reference/sram_manual/`；规格整理位于 `docs/SRAM宏规格基线_2026-10-28.md`。功能模型不是主办方宏时序模型，不能替代 Liberty/厂商模型。

## 时钟、复位和参数

- 所有逻辑使用单一 `clk` 上升沿时序。
- 低有效异步复位 `rst_n` 仅复位控制器状态，不对宏存储阵列写零。
- 顶层综合探索应使用 `USE_SRAM_MACROS=1`，并由综合环境提供真实宏 black-box/网表模型。
- 当前功能模型使用 `EMA=3'd2`、`EMAW=2'd3`、`RET1N=1'b1`。
- PE 的 8+4 是当前功能延迟合同，不代表已完成物理分级流水设计。

| 配置 | 本轮固定值 |
|---|---|
| ADDR_WIDTH / DATA_WIDTH | 32 / 32；DATA_WIDTH 是控制数据宽度，System Bus 与 SRAM 数据始终 16 |
| STRICT_COMPETITION_SHAPES | 1；支持 99×64×256 与 99×256×64 |
| USE_SRAM_MACROS | 必须显式设 1；源码默认 0 是旧行为缓存路径 |
| ROW_TILE / COL_TILE / K_TILE / K_BLOCKS | 8 / 16 / 32 / 8（顶层内部固定） |
| CACHE_ADDR_WIDTH | 10（16-bit word 地址） |
| MAC | 非融合 FP32 乘加；乘法 8 拍、加法 4 拍功能延迟 |

`constraints/fp32_sram_exploratory.sdc` 提供 150 MHz（6.666667 ns）探索时钟。没有臆造 IO delay、负载或 SRAM 时序；这些必须随真实平台与宏库补齐。完整任务仿真使用 10 ns 周期；功能 PASS 不证明 150 MHz 收敛。

## 综合复现

```powershell
# 实际功能回归入口（需本机已准备的 MSYS2/UCRT64 工具）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-SramFullLayerVerilator.ps1 -TwoLayers -OutputDirectory build/sram_two_layers_replay

# 综合侧请使用本包内 rtl/files.f 和顶层，在目标工艺宏库/black-box 条件下运行自己的 Yosys + Slang 流程。
```

综合侧需要补充：目标工艺 SRAM 宏模型、时钟约束（目标 150 MHz）、复位约束、宏 black-box 定义和最终面积/时序/功耗报告。

前端复现核心命令（任意工作环境需先配置正确 Verilator PATH）：

```text
verilator --lint-only --timing --assert -sv -DSYNTHESIS --top-module fp32_accelerator_top -GUSE_SRAM_MACROS=1 -GSTRICT_COMPETITION_SHAPES=1 -f rtl/files.f
```

Yosys/Slang 请读取包内固定 filelist，指定上述参数、真实 macro wrapper 和目标库，先做可综合性检查。不要综合 `tb/` 模型，不要用本包 SDC 的不完整 IO 条件发布正式 PPA。原有 `$fatal` 仿真断言隔离和 streamer 局部变量修复保留在主源码；不保证除此以外所有前端问题均已解决。
