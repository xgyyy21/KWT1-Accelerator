# 给软件同学：DMA 综合修复版本说明

日期：2026-11-01

## 源码身份澄清

已确认 `rtl/fp32_tile_dma_sequencer.sv` 的本地未提交修改是有意的综合兼容性修复：移除 `always_ff` 调用的 `advance_half_or_element` task，把同一状态更新逻辑内联到唯一时序块。数据布局、地址生成、FP32 低/高半字顺序、控制协议和 DONE 语义均未改变。

该文件 SHA-256：

`8f25945b8f222fab45474915f61c3ea3171be1e76161c4472a182e59e254b61b`

软件侧 2026-10-31 的 Golden 复核报告记录的实际测试文件 SHA-256 与此完全一致。因此，合成全 +1.0 和真实 KWT-1 第 0 层两组 Golden 功能数值及写回签收，已经覆盖这份 DMA 修改后的源码字节；其余验收边界不变：软件没有重新运行 RTL，真实 SRAM 宏、E203/E302 SoC、CPU DONE 后读回和物理时序仍未验收。

## 新的硬件基线

本说明与 `rtl/fp32_tile_dma_sequencer.sv` 单独提交，作为 `995a934` 之后的综合兼容性基线，不改写旧 Golden 归档的身份；具体提交号以 Git 提交记录为准。

本地 Icarus Verilog/vvp 14.0 devel 回归：9/9 通过，覆盖 DMA、连续任务、阵列分块、写回及顶层端到端任务。证据目录：

`build/dma_sequencer_inline_regression_2026-11-01_v1/`

综合前端复核尚待综合同学完成；这台机器没有可执行的 Yosys/Slang，不能据功能仿真替代综合确认。
