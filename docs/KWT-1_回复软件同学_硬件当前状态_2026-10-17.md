## 当前已经可以确认的硬件事实

### 1. 脉冲矩阵和分块

- 阵列结构为参数化 `ROWS=8`、`COLS=16`，共 128 个 PE。
- A 数据从左侧输入，B 数据从上侧输入。
- 已有输入 skew、valid/first/last、busy/done 和 tile 结果收集。
- `matrix_task_scheduler` 支持 M/N/K 分块和边界 tile。
- `ai_engine_regs_tb.sv` 已写入并检查 `M=99`、`K=64`、`N=256`。
- `matrix_task_scheduler_tb.sv` 已测试 99x64x256 的分块坐标。
- 当前没有完整的 99x64 x 64x256 数值结果测试，不能据此宣称首层已通过。

### 2. 缓存和 DMA

`matrix_cache_manager` 当前参数为：

```text
DATA_WIDTH = 16
ADDR_WIDTH = 10
DEPTH     = 1024
```

因此 A、B、result 各自为 1024 个 16 位字，即 2 KiB。读是同步读，读请求在下一拍产生有效数据。当前缓存没有 bias 专用区域；bias 如何放置需要由软件和硬件共同确定。

`tile_dma.sv` 当前只产生 A/B/result 地址、valid 和 result_ready 握手，尚未连接真实 SRAM 数据总线和缓存写入/读出路径。因此软件提出的“8 行输入、K=32 权重块、跨两个 K 块保留部分和”的方案在容量上可行，但还不是当前 RTL 已验证的正式实现。

### 3. 当前寄存器边界草案

`ai_engine_regs.sv` 当前偏移为：

| 偏移 | 名称 | 当前含义 |
|---:|---|---|
| `0x00` | CTRL | bit0=start，bit1=clear done，bit2=clear error |
| `0x04` | STATUS | bit0=busy，bit1=done，bit2=error |
| `0x08` | SRC_A | A 基地址寄存器 |
| `0x0c` | SRC_B | B 基地址寄存器 |
| `0x10` | DST | result 基地址寄存器 |
| `0x14` | M | 矩阵行数 |
| `0x18` | K | 归约维度 |
| `0x1c` | N | 矩阵列数 |

这些是硬件内部寄存器边界，不是已经批准的 E203 物理基地址或最终驱动 ABI。`req_ready` 当前恒为 1，读响应为一周期边界；真实 System Bus/NICE 包装尚未完成。

- RTL testbench：22/22 通过
- `ai_engine_soc_adapter` elaboration：通过

```powershell

  -Iverilog D:\competition\.tools\iverilog\bin\iverilog.exe `
  -Vvp D:\competition\.tools\iverilog\bin\vvp.exe
```

当前回归脚本的 FP32 向量路径依赖运行目录，因此需要先显式生成到共享副本的 `build/`。该目录被 `.gitignore` 排除。

## 尚未能够向软件确认的内容

以下内容现在不能给出“已确定”答复：

1. FP32 乘法/加法是否融合、每步舍入时刻和 NaN/非规格化数处理。
2. 最终 bias 加法的位置、累加顺序和跨 K 块保留方式。
3. FP32 32 位数拆成两个 16 位 SRAM 字时的高低字顺序和字节序。
4. 外部 X/W/b/Y 的正式基地址、步长和写回地址。
5. CPU、DMA 和加速器之间的数据搬运责任。
6. `DONE` 对 CPU 可见的最终时刻、屏障和连续任务协议。
7. 150 MHz 下的周期、面积、功耗和吞吐量。
